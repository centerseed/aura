🚀 SAM System (Stability-first Attention Management)

副標：用營運思維，管理個人與創業者的日常複雜度

一、 產品核心定位

SAM 不是替使用者做決定，也不是替使用者承擔後果；而是將高熵、零散、即時湧入的日常資訊流，轉化為**「穩定、可快速確認是否失控」**的狀態視圖。其目標是降低「維持整體不失控」的心智成本。

二、 核心架構：雙軸穩定模型 (Dual-Axis Stability Model)

SAM 以兩個正交維度，將所有輸入資訊轉化為可控狀態，避免資訊與任務失控。

1. 橫軸：狀態 (Status) —— 決定「注意力配置」

狀態不是分類，而是注意力與確認頻率的預設值。

狀態名稱

定義

注意力預設值

系統行為

[Active] 進行中

需要近期行動或決策的事項。

高頻確認

主動呈現、容許不完美但不可失聯。

[Maintain] 維持中

需長期維持、不需頻繁介入的事項。

異常觸發

平時隱形，僅在「不穩定」時亮燈指示。

[Reference] 知識備存

不影響當下狀態、純供參考的資產。

被動喚醒 (Context-based)

由 LLM 自動歸檔，平時隱形。僅在使用者處理相關 [Active] 任務時，由 AI 自動檢索並推送背景資訊。

2. 縱軸：實體 (Entity) —— 決定「歸屬感」

實體不是用來找資料，而是用來避免「事情彼此脫鉤」，建立完整的上下文。

領域 (Area)：事業、產品、個人、行政等。

主體 (Project / Subject)：某個專案、公司、客戶、特定角色。

主題 (Topic)：具體議題或問題空間。

三、 設計哲學 (Design Philosophy)

注意力優先於資料完整性：
不是所有資訊都需要被看見，但所有資訊都必須在「對的位置」。

狀態穩定性 > 即時最佳化：
系統關心的不是每一刻是否最優，而是使用者能否隨時確認「目前是否穩定」。

方法論內建，而非教育使用者：
使用者不需要理解理論，而是在低摩擦的使用中體驗秩序。

四、 輸入即整理：低摩擦資訊流處理

SAM 透過 AI 中間層消除管理摩擦，實現單一入口管理。

單一輸入入口：接受文字、語音、即時碎念，不要求預先分類。

系統自動處理：

解析動作：拆解為可行動項目或純資訊。

自動掛載：根據語意放入合適狀態，並掛載至對應實體。

容錯機制：不追求「一次就對」，目標是避免「越用越亂」。

五、 日常節奏設計 (Operational Rhythm)

透過固定節奏的自動化輸出，降低確認成本。

晨間簡報 (Morning Brief)：

聚焦今天需要關心的少數重點。

預警潛在的衝突或風險（如開發案與行政日程重疊）。

每日總結 (Daily Summary)：

回顧今天的狀態變化。

確認 [Active] 是否卡住，以及 [Maintain] 是否仍然穩定。

六、 儀表板設計原則：狀態檢視 (The Dashboard)

SAM 的介面不是資訊堆疊，而是「狀態的即時反饋」。

全局穩定視角：

Active 負荷監測：確認目前處理的事項是否過載。

Maintain 異常偵測：監控長期任務（如財務、簽證維護）是否亮起黃/紅燈。

狀態指示優於清單完整性：

🟢 綠燈：穩定，不需關心。

🟡 黃燈：需要注意。

🔴 紅燈：需要即刻介入。

情境展開 (Progressive Disclosure)：

只有在點擊某一項目時，才展開細節與關聯的 [Reference] 資訊。

七、 系統邊界與責任

SAM 提供：穩定的方法論、降低管理摩擦、避免失控。

使用者保有：最終決策權與行動責任。

八、 知識與檔案的生命週期 (Knowledge Management)

SAM 將知識視為「待喚醒的資產」，而非「待整理的負擔」，核心由 LLM 執行自動化管理：

1. **LLM 自主歸檔 (Auto-Filing)**：
使用者無需決定存儲路徑。LLM 根據內容與實體標籤，自動將文件寫入對應的物理資料夾（如 `/01_Legal` 或 `/04_Product`），並執行語意化命名規範（如 `YYYYMMDD_主題.md`）。

2. **語意索引與跨域關聯 (Semantic Indexing)**：
檔案在物理上雖位於單一位置，但 LLM 會建立多維度的語意索引。一份「專案合約」會同時被標記為 `[法律]` 與 `[該專案名稱]`，打破目錄樹狀結構的限制。

3. **主動上下文注入 (Contextual Injection)**：
這是 SAM 最核心的減壓機制。當使用者開啟某個 [Active] 任務時，LLM 會掃描全域備存，自動摘要相關背景、歷史碎唸或會議記錄，實現「資訊主動找人」。

4. **知識重構 (Refactoring Guidance)**：
系統會定期識別知識庫中的「高頻詞」或「混亂區」，在晚報中主動提議：*「老闆，我看你最近有很多關於 X 的碎唸，要不要為它獨立開一個專案實體？」* 藉此保持系統結構的長期穩定。

核心價值：讓人不必一直盯著，也不容易失控的個人營運系統。
