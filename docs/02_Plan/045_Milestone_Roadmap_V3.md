# Zentropy Milestone 發展藍圖 V3

**版本**: 3.0
**日期**: 2026-03-04
**基於**: V2 藍圖 + 「保護動能、順應人性」的戰略轉折（放棄精準估時，消除決策罪惡感）

---

## 產品戰略轉折：從「揪出偏差的訓導主任」到「保護動能的營運夥伴」

Zentropy 的核心價值不是逼迫用戶精準估計時間，也不是讓用戶面對計畫失敗的軟弱。用戶的核心渴望是**「趕快產出成果 (Ship fast and show the world)」**。

- **放棄傳統看板的罪惡感**：Kanban 是死板的容器，當實際進度和計畫脫節，用戶只會感到焦慮，最終逃避使用工具。
- **Zentropy 的破局點 (Momentum > Planning)**：我們不逼用戶填寫工時。我們偵測你的「狀態與手感」，當你在某個專案勢如破竹時，系統主動幫你把阻礙推開，重新對齊計畫，讓你安心把成果做出來。
- **行銷核心主軸**：「這世界上不缺另一個逼你精確預估時間的待辦清單，你需要的是一個能保護你動能的夥伴。」、「不要浪費生命做計畫，你只管產出。」

## Milestone 3: Momentum Protection (動能保護與焦點對齊)（4-6 週）

> **目標**：不再用「紀律」要求用戶，而是透過「追蹤實際動能」來消滅罪惡感，順水推舟。
> *(註：取代原先的 M3 治理與 M3.5 Episodic Memory 估時系統)*

### 3.1 Project 優先度標示 (零摩擦設定) ✅ 已實現
**設計理念**：提供清晰的極簡優先度介面，AI 只讀取不預判，保留用戶的絕對掌控感。
- 4 級制 (P0 核心, P1 重要, P2 維護, P3 待機)。
- Web/Flutter 提供卡片顏色標示與一鍵下拉切換。
- Todo List 底層排序永遠以 P0 為最優先。

### 3.2 動能追蹤儀表板 (Momentum Tracker) ✅ 已實現
**設計目標**：不看「預估 vs 實際耗時」，只看「你最近把精力都揮灑在哪裡」。
- 累積用戶「已劃掉 (ARCHIVE)」的任務軌跡。
- 視覺化近 7 天/ 14 天的「手感分佈」：以 Project 為群組，看出哪裡是目前的產出熱區。
- *(後端 API 與 Web UI `focus-bias-panel` 已實作完成)*

### 3.3 Coach 順毛摸介入 (Magic Moment)
**設計目標**：當計畫與實際脫節時，消滅用戶的罪惡感，鼓勵他們順著當下的手感一路衝刺。
- **觸發情境**：系統發現 P0 專案毫無進展，但 P2 專案卻完成了 15 個任務 (極強的動能)。
- **過去的作法（錯誤）**：指責用戶偏離 P0，要求回歸正軌。
- **Zentropy 的作法（Magic Moment）**： Coach 主動提示：
  > 「我注意到你這幾天在『專案B』勢如破竹！既然手感這麼順，我們不如直接把『專案B』升級為 P0，把原本的計畫先暫停？你今天就無懸念地把 B 趕快收尾發表吧！」
- 用戶只需一鍵點擊 `[升級專案 B 為 P0]`，瞬間完成計畫對齊，零罪惡感地繼續產出。

> **目標**：以「動能保護」作為最大差異化武器，驗證市場反應與付費意願 (WTP)。

### 5.2 用戶驗證與 Launch
- **招募標準**：擁有多重角色、目前苦於任務推進的斜槓/創業者。
- **核心驗證問題**：
  - 「Zentropy 的教練提示，有沒有讓你減輕拖延的罪惡感？」
  - 「一鍵對齊優先度後，是不是更容易專注產出了？」
- **行銷切角**："Your momentum is everything. Zentropy aligns your tasks to your current flow, not your past plans."

## Milestone 6: Active Builder（原 Planner，12 週）

> **目標**：消滅用戶面對大目標時的「起步認知摩擦」。只要有點子，系統瞬間注入專業領域知識，幫你轉成可以直接按 `[完成]` 的衝刺清單。
> **戰略定位**：Don't plan. Just build. (跳過規劃地獄，直接動手產出)

### 6.1 Brain Dump 與 Active Builder 的關鍵差異
為了避免用戶混淆，我們在產品設計上明確區分兩者的定位：
- **Brain Dump (整理已知)**：用戶「已經知道」要做什麼，系統負責擷取、分類。
- **Active Builder (注入未知)**：用戶「不知道」具體步驟，只有一個終極目標（如「學會 Next.js」）。Builder 調用 AI 的領域知識（Skill），**無中生有**生成一份具體的行動分解清單。

### Phase 1（M6 前 4 週）：高價值產出 Skills 上線
> **核心精神**：不逼問用戶細節，直接給付一份高水準的預設執行計畫，讓用戶可以直接挽起袖子開工。打破用戶「無知之幕」，給予具體執行清單。

- **Skill 1: 最小可行性產品 (MVP) 解構器**
  - **針對受眾**：創業者、獨立開發者、Side Hustle 玩家。
  - **觸發與魔法**：輸入「我想做一個記帳 APP MVP」。系統不只排 Coding 任務，而是依「精實創業」架構拆解：先找用戶訪談 (驗證期) -> 畫 UI (設計期) -> 核心功能實作 (實作期) -> 早鳥文案 (上線前)。
- **Skill 2: 逆向工程發布法 (Reverse-Engineering Launch Planner)**
  - **針對受眾**：內容創作者、活動主辦人、獨立開發者。
  - **觸發與魔法**：輸入「10 月 1 日要發布線上課程」。系統從終點往回推 (Backcasting)，排定「發布前 4 週預熱」、「發布前 2 週串接金流」等具體事項，完美融合進 Zentropy 的 Due Date 系統，拒絕死線前崩潰。
- **Skill 3: 主題式知識重構器 (The Feynman Learner)**
  - **針對受眾**：跨界學習者（如設計師學寫 Code）。
  - **觸發與魔法**：輸入「兩個月學會 Python 爬蟲」。系統不給死板課表，而是依照「吸收 -> 模仿 -> 實踐大挑戰 -> 費曼輸出分享」的循環排定，並直接轉為每日/每週 Task，將學習無縫融入日常管理。

### Phase 2（M6 第 5–8 週）：動能拯救與外包 Skills 上線
- **Skill 4: 情緒降壓除錯法 (Crisis Demolition)**
  - **針對受眾**：面臨巨大壓力、專案嚴重卡關、產生逃避心理的人。
  - **觸發與魔法**：當 Coach 發現 P0 專案大停滯，用戶表示「網站改版做不下去太焦慮」。Skill 將專案切碎成「奈米任務 (Nano-tasks)」，如「開 Google Doc 抓一個錯字就好 (10分鐘)」，用極低門檻重啟停滯的動能 (Momentum)。
- **Skill 5: 一人公司外包指引 (Delegate Planner)**
  - **針對受眾**：業務量爆炸的一人公司、準備擴張的小老闆。
  - **觸發與魔法**：輸入「辦一場 100 人實體論壇」。系統直接拆解為三區塊：老闆親自做 (找講者)、建議 AI 自動化 (報名信)、建議外包 (找場地/背板設計)。從管理層面直接解決不必要的親力親為。

### 6.2 務實防呆機制：漸進式升級 (Progressive Escalation)
> **設計決策**：徹底放棄依賴 LLM 大語言模型去「通靈」判斷使用者的輸入是「大專案還是小任務」（因為這在多國語系中極度不可靠且難以維護）。我們改用 100% 確定性的 UX 機制來處理。

- **統一入口，預設為小任務**：所有的 Brain Dump 輸入，預設都只會建立成普通的「單一 Task」。系統不擅自攔截或預判。
- **一鍵呼叫 Builder (User-Driven)**：如果使用者建立了一個太龐大的任務（如「經營自媒體」），當他點開該 Task 的詳細畫面時，畫面會提供一個常駐按鈕：`✨ 請 Builder 幫我拆解這個任務`。
- **好處**：完全沒有多國語系解析錯誤的問題，且將依賴性降到最低。任務要不要被拆解，決定權 100% 交還給使用者（Zero-guesswork）。

### Phase 3（M6 第 9–12 週）：自訂 Skill 請求
- 用戶可以向後台申請特定情境的自動拆解邏輯（例如：「幫我規劃 YouTube 影片製作」）。
- 用戶不接觸底層 Prompt，由官方維護更新，保證治理體驗的一致性與零摩擦。

## 關鍵設計決策記錄 (DDR 更新)

### DDR-001：Project 優先度不用 AI 推斷
優先度由用戶顯式設定，因為重要性涉及個人核心價值觀，AI 憑空推斷會侵犯用戶主體性。

### DDR-002：用戶驗證與 M3 並行
不再等待功能完成才找用戶。在 M3 開發期間同步進行深度訪談，尋找能激發他們「動能」的真正障礙。

### DDR-003：Planner/Builder 不暴露 Skill 給用戶
用戶只看到一個輸入框「幫我規劃……」，後台自動匹配。防止用戶陷入「自己寫 prompt」的治理地獄。

### DDR-004：Builder 是治理引擎延伸，不是獨立工具
確保產出的內容經過 Zentropy 結構化格式，不破壞核心資料的單一性。

### DDR-006：捨棄 Episodic Memory 的時間精準度追蹤（戰略轉折）
**決定**：完全移除原訂的「估計時間 vs 實際時間」偏差追蹤功能。
**理由**：用戶不需要另一個逼他們面對現實軟弱的工具。追蹤時間會讓 Coach 變成苛刻的監工，導致焦慮與逃避心理。我們轉向追蹤「實質動能 (Momentum)」，讚美用戶的產出成果，並讓計畫順應他們當下的手感，成為真正的營運夥伴。

### DDR-007：金流切換時機點
**決定**：在設立法人的手續與企業銀行帳戶完成之前，透過 Fake Door Test 測試付費意願，不串接任何個人金流。
**理由**：保障日本創業簽證與稅務合規，避免金流混淆造成的簽證風險。這 1-2 個月的等待期，恰好作為 M3 動能保護與 M6 快速規劃的開發衝刺期，等到上線時直接進入法人帳戶收割。

## 附錄：未來戰略擴充 - LINE 代理式體驗 (Agentic UX via LINE)

> **設計洞察**：一般用戶排斥自己設定工作流（如 OpenClaw 等），但內心極度渴望擁有一個「隨傳隨到、主動提醒、且不用學新系統的超級特助」。
> **解法**：將 Zentropy 的「治理引擎」與「主動 Planner」隱藏在單一個 LINE 官方帳號背後，利用「單一官方帳號 + 影子帳號 (Shadow Account) + LIFF 無縫轉正」的 SaaS 級架構，打造超越原生 App 的零摩擦獲客與代理式體驗 (Agentic UX)。

### 1. 零摩擦起手式 (LINE-First Onboarding)
- **情境**：潛在用戶從口碑看到 Zentropy，掃描加 LINE 好友，直接傳送第一句話：「幫我記下明天開會」。
- **無縫接招**：系統後台利用其 `LINE User ID` 建立「影子帳號」存入 Inbox，並回覆：「✅ 已記下！點擊綁定 Email 開啟完整教練面板」，透過 LIFF 瞬間帶入身分與筆記，完成無痛註冊。
- **價值**：先給予價值（成功紀錄與回饋），再要求註冊，以此漏斗極大化獲客轉換率。

### 2. 晨報推播與主動關心（The Coach 的極致展現）
- **晨報推播 (Push API)**：不再被動等待用戶開啟 App。每天早晨透過 LINE 推播：「早安！今天 P0 有兩項，另外提醒您停滯的 P1 專案，要不要趁今天推進一點？」
- **順毛摸介入 (Magic Moment)**：偵測到用戶處理雜事的手感極佳時，LINE 自動跳出：「教練觀察到您今天處理雜事手感極熱！🔥 要不要一鼓作氣把下週的報稅單提前到今天處理完？」用戶在一鍵點擊中完成計畫對齊。

### 3. 被動收集，主動蓋樓 (Active Planner 延伸)
- **情境**：用戶等車時隨手丟一句：「下個月要去東京考察無人店」。
- **主動提問**：Zentropy 收下後，Agent 判斷這是龐大目標，幾分鐘後在 LINE 反問：「已記下！這看起來需要規劃，要不要我現在幫您自動展開『前置研究』與『行程表』的 Task 清單？」
- **價值**：用戶只需「出一張嘴」，繁瑣的結構化拆解與專案初始化全由背後的 Zentropy 引擎代勞，完美提供「免設定、無腦養特助」的安全感與依賴感。

## 附錄 2：Active Planner 體驗差異化 (Zentropy vs. 通用 ChatGPT)

> **設計洞察**：如果 Active Planner 只是把用戶的話轉給 LLM 然後印出清單，用戶不如直接用 ChatGPT。Zentropy 的護城河在於將「AI 智商 (LLM 通用知識)」與「用戶魂器 (歷史記憶 + 當前動能)」結合，提供獨家的「個人營運處方笺」。

### 差異 1：結合「個人規劃記憶 (Episodic Memory)」
- **直接用 ChatGPT**：給出的估時是「大眾平均值」或「AI 幻想值」（如：架構設計建議 2 天）。
- **Zentropy Planner**：系統將用戶歷史的 `bias_ratio`（偏差值）當作 Context 餵給 LLM。
- **體驗昇華**：產出計畫時，Zentropy Coach 會補充：「根據歷史數據，您在開發類任務平均低估 2.1 倍。此份規劃清單已將您的偏差值列入計算，建議預留 4.5 天。」提供寫實、成功率更高的量身定做計畫，而非冷冰冰的 AI 樣板。

### 差異 2：結合「現有專案狀態 (Current Momentum)」
- **直接用 ChatGPT**：產出一份孤立的清單。用戶需自行煩惱「我本週已經三個緊急專案了，這個新清單要塞在哪裡」。
- **Zentropy Planner**：系統知道用戶的「盤面」。
- **體驗昇華**：生成計畫後，Zentropy Coach 會主動提議：「已為您展開此專案。但我注意到您的 P0『產品發表』已全滿且落後，為保護您的動能，我建議將此新計畫預設放入『P2 維護區』，要現在為您套用嗎？」——**不製造更多焦慮，而是主動管理焦慮。**

### 差異 3：封裝為「可執行系統物件 (Actionable Objects)」
- **直接用 ChatGPT**：產生一坨 Markdown 文字。把文字轉換成動作的過程（建專案、設 Due Date、分拆 Subtask）充滿腦力摩擦。
- **Zentropy Planner**：當用戶按下 `[🚀 建立專案並匯入]`，系統在背景瞬間建立所有 Task 實體，自動串聯階層，甚至自動配置 Cron（重複屬性）。
- **體驗昇華**：用戶體驗到真正的 **Agentic Workflow (代理工作流)**，感覺就像是由特助開完會後，親自將所有任務卡片建好放入系統，用戶只需無腦照著執行。
