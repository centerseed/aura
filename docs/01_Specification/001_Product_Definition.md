# Zentropy Product Definition (產品白皮書)

**Ver 4.0 — 一人多角時代的 AI 營運長**

Zentropy 是為「一人分飾多角」的現代人打造的 AI 營運系統。它不是又一個筆記軟體或待辦清單，而是一組具備主動治理能力的虛擬幕僚團隊——自動接收、分類、歸檔、預警——讓你在角色切換的日常中，不再害怕漏掉任何事。

---

## 1. 核心哲學：主動治理對抗熵增

### 問題：成功帶來的熵增 (The Entropy of Success)

現代人的生活越來越「多角化」：

- 上班是工程師，下班是自媒體創作者，週末是社群活動召集人
- 白天管三個客戶專案，晚上處理自己的 Side Project
- 同時是創業者、產品經理、財務、業務、客服

每多一個角色，資訊輸入就指數增長。研究顯示：

- **Context switching 每次消耗約 20% 認知容量**，重新聚焦需要 23 分鐘
- 工具碎片化 + 頻繁切換可**吞噬 40% 生產力**
- 多任務處理者完成任務**慢 25%、錯誤多 50%**

傳統工具（Notion、ClickUp、Google Tasks）是被動容器——它們不會自己整理。結果是：**越忙碌的人，數位生活越像一個堆滿雜物的倉庫**，帶來決策疲勞與「怕漏掉什麼」的潛在焦慮。

### 解答：主動治理 (Active Governance)

Zentropy 的核心假設：**只有「主動治理」才能對抗熵增。**

系統必須像一個訓練有素的幕僚團隊，不只「儲存」資料，而是主動進行：

1. **聚合 (Aggregation)**：將碎片化的輸入拼湊成完整敘事
2. **定位 (Triangulation)**：識別資訊屬於你的哪個角色、哪個專案
3. **歸位 (Transition)**：根據事務的急迫性與性質，放入正確的狀態抽屜

## 2. 目標用戶：一人多角的營運者

### 核心 Persona

> **同時扮演多重角色、手上跑 3+ 個平行事務線、沒有專職助理或 PM 的人。**

他們最大的痛點不是「缺功能」，而是：

- **腦中同時跑太多事，怕漏掉**
- **沒時間整理資訊，但不整理就失控**
- **需要有人幫他看全局、抓衝突**

### 具體用戶畫像

| 類型 | 典型樣貌 | 核心痛點 |
|:---|:---|:---|
| **微型創業者** | 1-5 人團隊負責人，同時管產品、財務、業務 | 沒有 PM 幫他兜底，事情掉了沒人接 |
| **斜槓工作者** | 白天上班、晚上接案或經營副業 | 角色切換時資訊混在一起，公私不分 |
| **自由工作者** | 同時服務 3+ 個客戶的設計師/開發者/顧問 | 每個客戶一套溝通方式，context 碎片化 |
| **多重身分者** | 工程師 + 社群經營 + 投資理財 + 家庭 | 生活面向太多，永遠覺得什麼沒處理到 |
| **AI-Native 建造者** | 用 Cursor/Claude 工作，需要被 AI 讀取的知識庫 | 現有工具無法與 AI 工作流深度整合 |

### 為什麼不是「所有忙碌的人」？

| 維度 | 一般忙碌上班族 | 一人多角的營運者 |
|:---|:---|:---|
| 痛點強度 | 中（有組織幫他兜底） | **極高**（沒人幫他兜底） |
| 付費意願 | 低（公司買單 or 免費工具夠用） | **高**（省下的時間直接 = 收入或生活品質） |
| Notion/ClickUp 能解決？ | 大部分能 | **不能**——花更多時間設計模板，而非實際工作 |
| Zentropy 的差異化 | 模糊 | **清晰**——開箱即用的 AI 幕僚團隊 |

## 3. 系統本體論 (The System Ontology)

Zentropy 透過三層架構映射用戶的多重角色與資產：

| 層級 | 概念 | 定義 | 範例 |
|:---|:---|:---|:---|
| **L1** | **Area (角色)** | **「我是誰？」** — 長期身分認同與責任邊界，也是隱私隔離的容器。 | `工程師@公司`、`創辦人@副業`、`個人生活` |
| **L2** | **Product (資產)** | **「我在經營什麼？」** — 具備產出價值或需持續維護的資產實體。 | `後端系統`、`健康管理`、`Q3 財報` |
| **L3** | **Topic (性質)** | **「這是什麼類型的事？」** — 行動類型的聚類屬性。 | `功能開發`、`Bug 修復`、`策略規劃`、`例行檢查` |

這套架構的核心價值：**讓你的每個角色互不干擾，但又能在需要時交叉引用。**

## 4. 虛擬幕僚鐵三角 (The Agent Triangle)

Zentropy 的核心差異化：不是給你更多功能，而是給你**三位 AI 幕僚**。

### 4.1 The Gatekeeper (守門人) — 你的收件助理

- **職責**：NLU 感知與初步解析
- **運作**：24 小時待命，接收來自文字、語音、照片的碎片化輸入
- **價值**：你只管「丟進來」，它負責理解你在說什麼、分到哪個角色、判斷緊急程度
- **解決的痛點**：不用花時間思考「這個該放哪裡」

### 4.2 The Librarian (圖書管理員) — 你的檔案專員

- **職責**：熵減與智慧歸檔
- **運作**：
  - **Rolling Memory**：維護每個角色 (Area) 的長期記憶摘要
  - **Auto-Classification**：基於 L1-L3 架構自動歸類
  - **Cross-Reference**：自動檢索並推薦相關的歷史資訊
- **價值**：資訊自動歸位，再也不會「我記得有這份資料但找不到」
- **解決的痛點**：不用花時間整理，但資訊永遠井然有序

### 4.3 The Coach (教練) — 你的營運總監

- **職責**：深化想法、規劃行動、監控執行與心理閉環
- **運作**：
  - **深化想法 (Refine)**：Brainstorming 夥伴——質疑假設、補充盲點、將模糊想法具體化為可執行路徑
  - **事務規劃 (Plan)**：根據任務時間軸、deadline、每日容量，生成「今天先做什麼」的行動計畫
  - **衝突偵測**：掃描行事曆與任務，預警時間衝突或資源撞車
  - **晨報 / 晚報**：每天兩次主動摘要，確保你對全局有掌控感
  - **規劃記憶**：追蹤估時 vs 實際完成時間，累積個人偏差因子，讓排程越來越準
  - **審核機制**：重大變更需你確認，系統不會擅自行動
- **價值**：你不用自己「盯全局」，有人幫你想清楚、排好順序、盯著進度
- **解決的痛點**：消除「想法太模糊不知怎麼開始」+ 「是不是忘了什麼」的睡前焦慮 + 「不知道該先做什麼」的決策癱瘓

## 5. 功能主軸：用戶與 AI 的五層互動

Zentropy 的功能演進遵循一條清晰的深度軸線：

```
丟進來 (Capture) → 幫我理 (Organize) → 幫我想 (Refine) → 幫我排 (Plan) → 幫我看 (Review)
```

| 層次 | 關鍵字 | 一句話定義 | Agent 負責 |
|:---|:---|:---|:---|
| **L1** | **Capture** | 零摩擦輸入——文字、語音、照片丟進來就好 | Gatekeeper |
| **L2** | **Organize** | AI 結構化 + 自動歸檔 + 標籤 + 合併重複 | Gatekeeper + Librarian |
| **L3** | **Refine** | 深化想法：brainstorming、補盲點、具體化執行路徑 | Coach |
| **L4** | **Plan** | 根據 deadline、容量、優先序排出每日行動 | Coach |
| **L5** | **Review** | 回顧偏差 + 停滯偵測 + 從歷史學習 | Coach |

### 晨晚報：L4 與 L5 的交界載體

**晨晚報不屬於單一層，它是橫跨 L4 Plan + L5 Review 的核心產品功能。**

| | 晨報 (Morning Briefing) | 晚報 (Evening Debrief) |
|:---|:---|:---|
| **L5 成分** | 昨日回顧：什麼完成了、什麼延遲了 | 今日回顧：完成率、偏差分析 |
| **L4 成分** | 今日規劃：排出優先序、預估時間 | 明日預告：明天的重點事項 |
| **觸發** | 每日 08:30 主動推送 | 每日 21:00 主動推送 |

晨晚報是用戶**每天固定接觸的 touchpoint**，也是「教練」人格感知最強的時刻。

### 重點突破策略

不平均分配五層，而是兩端做到極致：

| 層 | 投入 | 目標 |
|:---|:---|:---|
| **L1 Capture** | 重點投入 | 極致零摩擦，做到「丟進來就忘」 |
| L2 Organize | 維持現狀 | 自動歸檔能跑就好 |
| L3 Refine | 第二波 | 等 L1 + 晨晚報驗證後再做 |
| **L4+L5 晨晚報** | 重點投入 | 以晨晚報為載體，同時交付排程 + 回顧 + 偏差學習 |

**邏輯**：L1 是漏斗入口（決定留存），晨晚報是每日價值交付（決定黏性）。中間的 L2/L3 只要不出錯就好。兩端做到極致 = 「教練」定位，而非「又一個管家」。

Zentropy 的功能演進遵循一條清晰的深度軸線：

```
丟進來 (Capture) → 幫我理 (Organize) → 幫我想 (Refine) → 幫我排 (Plan) → 幫我看 (Review)
```

| 層次 | 關鍵字 | 一句話定義 | Agent 負責 | 狀態 |
|:---|:---|:---|:---|:---|
| **L1** | **Capture** | 零摩擦輸入——文字、語音、照片丟進來就好 | Gatekeeper | 已實現 |
| **L2** | **Organize** | AI 結構化 + 自動歸檔 + 標籤 + 合併重複 | Gatekeeper + Librarian | 已實現 |
| **L3** | **Refine** | 深化想法：brainstorming、補盲點、具體化執行路徑 | Coach | **未實現** |
| **L4** | **Plan** | 根據 deadline、容量、優先序排出每日行動 | Coach | 開發中 |
| **L5** | **Review** | 晨晚報 + 衝突偵測 + 停滯偵測 + 從歷史學習偏差 | Coach | 基礎已實現 |

### Execute 邊界

Execute 不是 Zentropy 的層，而是 Zentropy 的**輸出邊界**：

- **簡單動作**（建立 calendar 事件、發 Slack 訊息）→ Zentropy 透過 MCP 直接代勞
- **複雜執行**（寫程式、設計、談判）→ 用戶在自己的工具中執行，Zentropy 提供 context
- **結果回收** → 執行結果回流至 Review 層，形成閉環

### 互動深度定位

| 深度 | 系統角色 | 代表產品 | Zentropy 覆蓋 |
|:---|:---|:---|:---|
| **執行者** | 我說什麼你做什麼 | Apple Reminders | L1 |
| **管家** | 整理、歸檔、提醒 | Todoist、Things、Notion | L1-L2 |
| **軍師** | 排程行動 | Motion、Reclaim、Sunsama | L1-L4 |
| **教練** | 了解模式、質疑假設、從錯誤學習 | **無產品做到 ← Zentropy 目標** | L1-L5 |

### 關鍵洞察

**L4 Plan 不再是藍海：**
- Motion 與 Reclaim 的自動排程已經成熟。Zentropy 的 L4 差異化在於**基於多角色容量的智慧排程**——理解用戶同時扮演哪些角色、每個角色的精力預算，這是 Motion/Reclaim 不做的。

**L3 Refine 是真正的空白地帶：**
- 除 Heptabase 的白板 + AI 對話有部分觸及外，**沒有任何任務管理工具做「想法深化」**。Heptabase 偏向知識學習，Zentropy 偏向**行動導向**（模糊想法→可執行計畫），定位不同。

**L5 Review 幾乎無人觸及：**
- Sunsama 的「每日回顧」最接近，但仍是手動儀式，不是 AI 主動分析偏差並學習。「從歷史偏差學習」確實沒有競品在做，「教練」定位成立。

**OpenClaw 是長期需要關注的威脅：**
- 開源、自架、50+ 整合——理論上能做 L1-L5 所有事。但它是通用框架，沒有內建的任務管理本體論（雙軸模型、Entity 歸檔）。用戶需要大量自定義。類比：OpenClaw 是 Linux，Zentropy 是 macOS。

**Zentropy 差異化：**
- 唯一覆蓋 L1-L5 全鏈路，且以「教練」而非「工具」定位
- L3 Refine + L5 偏差學習 = 市場空白
- L4 的多角色容量管理 = 與 Motion/Reclaim 區隔

## 7. 核心價值主張

### 一句話

> **「你的 AI 營運長——讓一人多角的你，擁有三人幕僚團隊的掌控力。」**

### 五個承諾（對應五層）

1. **Zero Friction Capture (L1)**：語音、文字、照片——丟進來就好，零摩擦。
2. **Auto Organization (L2)**：你不再需要手動整理。AI 自動歸檔、標籤、合併重複。
3. **Smart Refinement (L3)**：想法太模糊？AI 幫你 brainstorm、補盲點、具體化為可執行路徑。
4. **Smart Planning (L4)**：根據 deadline、容量與優先序，排出「今天先做什麼」的行動計畫。
5. **Active Coaching (L5)**：晨晚報掌握全局、衝突預警、從歷史偏差學習——你的 AI 教練越用越懂你。

### 成功指標

- 用戶每天花在「整理」上的時間 < 5 分鐘
- 「怕漏掉什麼」的焦慮感顯著降低（NPS / 用戶訪談驗證）
- 跨角色的資訊檢索時間減少 80%

## 8. MCP 產品定位：無頭治理協議

Zentropy 不僅是一個 App，更是一套透過 **MCP (Model Context Protocol)** 為所有 AI Agents 提供上下文與治理能力的底層系統。

| 角色 | 功能 | 情境範例 |
|:---|:---|:---|
| **Context Provider** | 透過 `zentropy://` URI 暴露資料 | 在 Cursor 中寫程式時，AI 自動讀取 Zentropy 的 Spec 文件作為參考 |
| **Action Handler** | 提供 `capture_thought` 等 Tools | 在 Claude Desktop 聊出一個 Idea，一鍵存回 Zentropy 的 Inbox |
| **Governance Engine** | 提供 `reorganize` 能力 | 讓外部 Agent 也能觸發 Zentropy 的整理邏輯，維護知識整潔 |

**Vision**：To be the **"Operating System for Personal Agency"** in the AI era.
