## 1. Product Thesis

### 核心問題

你忙了一整週，但你說得出來這週最重要的事是什麼嗎？

大部分人答不出來。不是因為不努力，是因為**沒有人在幫你看你的努力正在往哪裡走**。

公司的任務有人管。但你自己的方向，沒有。

### 核心主張

Zentropy 做兩件事：

1. **管住混亂** — 把你腦子裡的東西理出頭緒
2. **看見方向** — 從你每天在做的事裡，照出你正在往哪裡走

第一件事讓你今天就有用。第二件事讓你用越久越離不開。

### 產品結構

Zentropy 不是「記事工具 + 自我成長模組」，而是一個閉環：

```
        ┌─────────────────────────────────┐
        │                                 │
        ▼                                 │
  ┌──────────┐                            │
  │   輸入   │ 任務 / 想法 / 討論         │
  └────┬─────┘                            │
       │                                  │
       ▼                                  │
  ┌──────────┐                            │
  │ 管住混亂 │ 理出頭緒，落在地圖上       │
  └────┬─────┘                            │
       │                                  │
       ▼                                  │
  ┌──────────┐                            │
  │ 地圖生長 │ 視覺成長、連結出現         │
  └────┬─────┘                            │
       │                                  │
       ├──→ 完成任務 → 反思 ──────────────┤
       │                                  │
       ▼                                  │
  ┌──────────┐                            │
  │ Insight  │ 有發現才說                 │
  └────┬─────┘                            │
       │                                  │
       └──→ 影響下一次輸入 / 討論 ────────┘
```

三個輸入入口：

- `任務`：要做的事
- `想法/心得`：要記的
- `討論`：要想清楚的 — 和 AI 一起把模糊的念頭想透，討論過程自動回饋到個人地圖

在資料架構上，這個閉環對應為：

- `Flow Layer`：承接輸入、立刻理出頭緒、處理完成與反思
- `Growth Layer`：地圖視覺化、每次輸入的即時成長、連結生長（Flow 和 Map 之間的視覺層）
- `Map Layer`：逐步形成個人地圖、偵測模式、產生 insight
- `ZenOS Core`：只承接高信心、慢變、值得治理的知識

Zentropy 的前台產品體驗不直接等於 ZenOS Core。前台先建立秩序與個人地圖，成熟的知識才 promotion 到 ZenOS。

### 產品北極星

> **讓使用者管住日常混亂，再從混亂裡看見自己的方向。**

### 核心張力

Zentropy 要同時滿足兩個條件：

1. 一開始就有立即價值（管住混亂）
2. 用久之後會變得更有意義（看見方向）

如果只做到第一點，退化成比較順的待辦或筆記工具。
如果只做到第二點，太抽象，無法成為下載理由。

閉環中的「完成反思」是連接兩者的橋——它把短期的行動變成長期的素材，但不強迫用戶每次都做。

### 非目標

- 不追求最強 PKM 系統
- 不追求最強任務管理
- 不追求一開始就做深度自我分析
- 不追求人格測驗式的產品心智
- 不做定期排程報告（不是週報工具）

## 2. Lean Canvas

### Problem

使用者的核心問題不是缺少工具，而是：

1. 每天很忙，但說不出來到底在忙什麼、在往哪個方向走
2. 腦子裡的東西（任務、想法、靈感、焦慮）沒有地方放，散在 Notes、Todo、Chat、腦子裡
3. 偶爾停下來想「我最近到底怎麼了」，但答不出來，因為沒有人幫你看全貌

### Customer Segments

主要客群：

- 常用 AI 的一般知識工作者
- 有記錄習慣但難以長期維持的人
- 想更理解自己目前生活重心，但不喜歡高負擔反思的人

早期採用者：

- 平常會把很多事記下來，但目前散在 Notes、Todo、Chat、書摘、連結收藏裡的人
- 曾試過 Obsidian、Heptabase、日記、Habit app，但難以持續的人

### Unique Value Proposition

> **管住混亂，看見方向。**

更具體地說：

- 先把每天腦子裡的東西理出頭緒
- 再從這些東西裡，照出你正在往哪裡走

### Solution

1. 三個輸入入口：`任務`（要做的）、`想法/心得`（要記的）、`討論`（要想清楚的）
2. 讓記下來的東西立刻比較有頭緒，而不是只進 inbox
3. 每次輸入都讓個人地圖視覺化地成長——不用等 insight，地圖本身就在說話
4. 完成任務時提供輕量反思入口（選擇性，不強迫）
5. 討論模式讓用戶和 AI 一起把模糊念頭想透，過程自動回饋到地圖
6. 有 insight 時主動浮現，不是定期推送

### Channels

- 既有網站與 landing page
- App Store / Google Play
- 社群短內容：忙到看不見方向、記了一堆但沒有用
- 自我成長 / 生產力 / AI 工具型 KOL
- 既有 Zentropy 用戶回流與轉介

### Revenue Streams

- Freemium：基礎記錄與整理免費
- 訂閱制：insight 解鎖、進階視覺化、AI 回饋、自我覺察框架
- 長期可擴展：主題型 insight packs、進階 personal coach 層

### Cost Structure

- LLM 與 embedding 成本
- 長期資料存儲與圖譜計算
- 視覺化與前端體驗
- 行銷獲客與 retention 運營

### Key Metrics

- 首日輸入次數
- 第 7 天仍持續輸入的比例
- 單用戶跨類型輸入比例（task / idea / discussion）
- 完成任務後填寫反思的比例（目標：自然不強迫，30%+ 即可）
- 用戶主動打開地圖查看的頻率
- 討論模式使用頻率與每次討論產生的 Map Layer 節點數
- Insight 被點開 / 產生行動的比例

### Unfair Advantage

- 不是從自我成長切入，而是從管住混亂切入——下載門檻低
- 地圖生長讓每次輸入都有即時視覺回饋，不需等 insight 才有價值
- 討論模式產生最高品質的輸入，一次討論長出一整片地圖區域
- 完成反思迴圈讓資料品質遠高於純輸入
- Zentropy 前台圖譜與 ZenOS Core 分層，consumer UX 與 canonical knowledge 可同時成立
- ZenOS 提供底層知識與治理能力，讓後續 insight 層更可持續演進

## 3. TA 與 Persona

### 核心 TA 定義

最核心的目標用戶不是最會自己搭工具的人，而是：

> **每天很忙、也知道自己應該想清楚方向，但沒有時間停下來整理的人。**

### Persona A：忙到失焦的知識工作者

- 身份：PM / marketer / 顧問 / 創作者 / 小型團隊成員
- 行為：
  - 腦中很多事情同時在跑
  - 常在聊天、記事本、待辦、書摘之間切換
  - 會用 AI，但不會自己搭記憶系統
- 痛點：
  - 忙了一整週，說不出來最重要的事是什麼
  - 知道應該停下來想想，但永遠沒有那個時間
  - 公司的任務有人管，但自己的方向沒有人看
- 期待：
  - 先讓腦子裡的東西不再一團亂
  - 然後有人告訴我：你最近到底在忙什麼、忽略什麼

### Persona B：反覆嘗試記錄系統但總是放棄的人

- 身份：自我成長型用戶、習慣 app 用戶、journaling 愛好者
- 行為：
  - 試過很多記錄方法與生產力工具
  - 一開始很有熱情，後來很難持續
- 痛點：
  - 系統太重、要先分類先整理先設計
  - 最後記錄變成額外工作
  - 記了一堆但從來沒有回過頭看出任何東西
- 期待：
  - 不需要先想清楚才能開始
  - 日常就能自然累積
  - 真的能從累積裡看到些什麼

### Persona C：想更了解自己但不想被教育的人

- 身份：對自我成長有興趣的一般用戶
- 行為：
  - 願意看書、願意思考、願意記一些東西
  - 但不喜歡被要求每天寫長反思或做深度心理分析
- 痛點：
  - 想更知道自己最近怎麼了
  - 但不想進入沉重的教練 / 治療 / 自我審判情境
- 期待：
  - 用自然、低壓的方式慢慢看見模式
  - 不被說教、不被強迫改變
  - 偶爾被提醒一下就好

### 不打的 Persona

- 會自己搭 PKM 與 AI toolchain 的 power users
- 只想要最強任務管理的人
- 只想要最完整筆記系統的人
- 期待一上來就做深度人生教練的人

## 4. Zentropy 是什麼

Zentropy 是一個幫你管住混亂、看見方向的工具。

### 三個入口

```
┌────────┐  ┌──────────┐  ┌────────┐
│  任務  │  │ 想法/心得 │  │  討論  │
│ 要做的 │  │ 要記的    │  │ 要想的 │
└────────┘  └──────────┘  └────────┘
```

- **任務**：一件要做的事。系統自動理出頭緒、連到相關脈絡、產生下一步建議。
- **想法/心得**：一個���頭、一段靈感、一句書摘、一個看到的東西。不用決定它是什麼，丟進來就比放在腦子裡清楚。
- **討論**：一個還沒想清楚的問題。和 AI 一起想透它——AI 會根據你的個人地圖提供脈絡，用思考框架幫你結構化，討論過程自動回饋到地圖。

### 管住混亂

你腦子裡每天會冒出一堆東西——待辦、想法、靈感、看到的資料、突然的焦慮。這些東西現在散在 Notes、Line 自己傳給自己的訊息、還有你的腦子裡。

Zentropy 先把這些接住。想到什麼就丟進來，不用分類、不用整理。

### 地圖生長

每一次輸入，你的個人地圖都在長。

不是列表變長。是一個**活的世界**在生長——你的工作區域越來越大、創作區域剛冒出新芽、健康那一塊還是空白。

你不需要等系統告訴你「你忽略了健康」。你一打開地圖就看到了——那一塊是空的。

完成任務後的反思會影響地圖的質感：高能量的事情讓節點發亮，消耗性的事情讓節點變暗。你一眼就能看出你的世界裡哪些區域活力充沛、哪些正在枯萎。

用了一兩週，節點之間開始長出連結——某天想到的一件事，和上週做的一件事，突然被連在一起。這些連結不需要系統解釋，你自己看到就懂了。

**你不是在記錄。你是在看自己的腦子長出形狀。**

### 討論模式

你有一個反覆在想的問題——「要不要換工作」「接下來該把時間花在哪」「為什麼最近一直覺得哪裡不對」。

討論模式讓你和 AI 一起把它想透：

- AI 會從你的地圖裡拉出相關脈絡（「你最近三週跟這件事有關的想法有 8 個」）
- AI 會用思考框架幫你結構化（5W1H、Pre-mortem、機會成本...），但你不需要知道框架名稱
- 討論中產生的想法、決定、發現，自動回饋到地圖

討論是最高品質的輸入。一次討論可以讓地圖長出一整片新區域。

### 看見方向

當輸入、反思、討論逐漸累積，Zentropy 開始發現你自己沒注意到的事：

- 你最近所有心力都在工作，但健康和關係完全空白
- 你每次提到某件事都特別興奮，但從來沒排時間做
- 你說最重要的事，和你實際花時間的事，不是同一件
- 有些事一直在消耗你，但它們都不是你真正在意的

這些 insight 不是定期推送的週報。是系統真的發現了什麼，才告訴你。

而且到了這時候，你往往已經從地圖上隱約感覺到了。Insight 不是驚喜，是確認——「對，我就知道哪裡不對。」

Zentropy 不告訴你該怎麼做。它只是把事實照給你看。改不改，是你的事。

### 完成反思迴圈

傳統的任務工具會在晚上告訴你「你還有 5 件沒做」。Zentropy 反過來。

完成一件任務時，它輕輕問一句：

> 「做完了。有什麼想法嗎？」

晚上，它不檢討你什麼沒做，而是把今天完成的事列出來：

> 「你今天完成了這些。有沒有哪件讓你特別有感覺？」

你可以：
- 寫一句感受（「比想像中順利」「其實不想做但不得不做」）
- 對某件完成的事點一個標記（有成就感 / 很消耗 / 沒感覺）
- 什麼都不做

這不是日記。不是打分。不是檢討。

但如果你偶爾留下一點東西，Zentropy 對你的理解會快很多——它不只知道你做了什麼，還知道你做完之後的感覺。而且它讓你的注意力放在「我做到了什麼」，而不是「我又拖延了什麼」。

這就是所有自我成長書都說最重要、但沒有人做得到的那一步。Zentropy 把它變成一句話或一個點擊。

## 5. 核心問題

### 問題 1：忙到看不見方向

你不是不努力。你每天都在做事、都在想事情。

但你說不出來：
- 最近到底在忙什麼
- 哪些事真的重要
- 現在的生活重心有沒有偏

問題不是不夠忙，是**看不見自己的忙在往哪裡走**。

### 問題 2：腦子裡的東西沒地方放

每天都會冒出一堆東西：待辦、想法、靈感、焦慮、看到的資料。

問題不是沒有工具，而是：

- 記到待辦裡太窄（不是每件事都是任務）
- 記到筆記裡太散（記了找不到）
- 記到聊天裡太容易消失
- 記錄之前還要先想分類，阻力太大

結果是很多東西根本沒被留下來，或者留下來之後很快就失去關聯。

### 問題 3：做了很多事，但從來沒有回頭看過

你完成了一件事，就跳到下一件。

很少有人會停下來想：
- 這件事做完我什麼感覺
- 這件事對我來說到底重不重要
- 我最近完成的事情，是不是都在同一個方向

不是不想停，是**沒有一個自然的時刻讓你停**。

所有自我成長書都說「觀察你的行動就能認識自己」。但它們都要你手動寫日記、填表格、每天反省——沒有人做得到。

## 6. Zentropy 的解法

### 第一層：管住混亂

這是產品最外層、最重要的下載理由。

Zentropy 先做的是：

- 三個入口：任務（要做的）、想法/心得（要記的）、討論（要想清楚的）
- 讓輸入後的東西不只是堆積，而是開始形成頭緒
- 不用先整理好才能輸入

這一層解決的是一個很眼前的問題：

> **腦子裡太多東西，需要一個地方倒出來，倒出來之後比較不亂。**

### 第一點五層：地圖生長

這是管住混亂和看見方向之間的橋。

**每一次輸入，你的個人地圖都在視覺化地生長。** 不需要等三週才有 insight。你今天丟了一個東西進來，地圖就變了一點。

#### 成長機制

每個主題區域（工作、創作、家人、健康...）有視覺上的成長階段：

- 輸入越多，區域越大
- 有反思的節點，質感不同（亮 = 高能量，暗 = 消耗）
- 沒有輸入的區域保持空白——**空白本身就是訊號**
- 用了一兩週，節點之間開始長出連結

#### 遊戲化元素（養成感，不是積分制）

| 元素 | 怎麼做 | 驅動力 |
|------|--------|--------|
| 養成感 | 區域從無到有慢慢生長 | 看見自己的投入有回報 |
| 發現感 | 新連結出現時有微動畫 | 好奇心，不是義務 |
| 收集感 | 地圖上的主題像解鎖的領域 | 世界越來越豐富 |
| 稀有感 | 高能量反思讓節點特別亮 | 偶爾的反思變成「特別的東西」 |
| 空白感 | 沒有輸入的區域保持空白 | 最安靜的提醒 |

**不做的事：** 不做積分、不做排行榜、不做連續登入獎勵、不懲罰不使用。

#### 為什麼地圖生長能驅動自發記錄

傳統 App 的記錄動機是紀律（「我應該記」）。Zentropy 的記錄動機是好奇心（「我想看看地圖現在長什麼樣了」）。

你不是在記錄。你是在看自己的腦子長出形狀。

### 第二層：完成反思

反思的起點不是「你今天什麼沒做到」，而是「你今天完成了什麼，感覺怎麼樣」。

傳統的任務工具會在晚上告訴你「你還有 5 件沒做」——這製造焦慮。
Zentropy 反過來：讓你看見你完成了什麼，然後問一句：

> 「做完了。有什麼想法嗎？」

這個翻轉是刻意的，對應《高效原力》的核心原則：不是「努力→成功→感覺好」，是「感覺好→生產力→成功」。從成就感出發，而不是從缺口出發。

#### 兩個反思時機

**即時反思（完成當下）：**

完成一件任務時，系統輕輕問一句。用戶可以寫一句感受，也可以跳過。

**晚間回顧（可選）：**

晚上不是檢討今天哪些事沒做到。而是：

> 「你今天完成了這些事。有沒有哪件讓你特別有感覺？」

把今天完成的事列出來，讓用戶選擇性地對其中一兩件留下回饋。不是所有都要寫，點一下「這件事讓我很有成就感」或「這件事做完其實很空虛」就夠了。

#### 設計原則

- **從成就出發，不從缺口出發**：永遠先展示你完成了什麼，不先展示你沒做什麼
- **絕不強迫**：跳過是正常行為，不是失敗
- **一句話就好**：不要求寫長文，一個感受、一個念頭就夠
- **語氣溫和**：不是考試，不是日記，不是教練在問你
- **有做就加分**：每一次反思都讓 Map Layer 的理解更深一層

#### 反思的價值

- 把行動和感受連結起來（你做了什麼 + 做完什麼感覺）
- 提供 Map Layer 最高品質的訊號（能量、滿足感、消耗感）
- 在最自然的時刻（剛完成一件事 / 一天結束時看成果）做最小的回顧
- 讓用戶的注意力放在「我做到了什麼」而不是「我又拖延了什麼」

這就是四本暢銷書都說要做、但沒人做得到的「好時光日誌」——Zentropy 把它變成完成任務後的一句話，或晚上看著成果清單的一個點擊。

### 第三層：看見方向

當輸入和反思逐漸累積，Zentropy 開始讓使用者看見自己的方向。

不是定期報告。不是排程推送。是**系統真的發現了什麼，才告訴你**。

#### Insight 類型與觸發條件

| Insight 類型 | 用戶看到的 | 觸發條件 | 底層框架 |
|-------------|-----------|---------|---------|
| 沉默警報 | 「你說健康很重要，但最近 28 天沒有想過任何跟健康有關的事」 | 某 life area 連續 N 天零輸入 | 生命之輪 |
| 能量峰值 | 「你每次提到寫作都特別有能量，但從來沒排時間做」 | 高能量主題 + 零行動 | SIGN / 好時光日誌 |
| 錯位提醒 | 「你說家人最重要，但最近一個月 90% 的心力在工作」 | 設定的價值 vs 實際分布顯著偏離 | 錯位偵測 / DYL 羅盤 |
| 消耗警報 | 「這三件事一直在消耗你，但它們都不是你真正在意的」 | 重複出現 + 負面語氣 + 非核心主題 | 三種倦怠 |
| 隱藏模式 | 「你可能沒注意到，但你最近三週提到創業 17 次」 | 特定主題累積超過閾值 | 活動審計 |
| 重心快照 | 「你現在的生活重心：工作 82%、創作 12%、關係 4%、健康 2%」 | 足夠資料後，週期性呈現 | 能量投資組合 |

#### Insight 的設計原則

- **有發現才說**：不是每天推送、不是週報、不是排程。是真的偵測到模式才浮現
- **事實不說教**：Zentropy 不告訴你該怎麼做，只照出事實。「這是你要的樣子嗎？」
- **來自你自己**：不是 AI 生成的建議，是從你自己丟進來的東西裡算出來的
- **可以不理**：看到了可以選擇不行動，沒有壓力

#### 底層框架（用戶不需要知道）

這些 insight 的底層使用的是多本暢銷書共同驗證的自我覺察框架：

- **生命之輪**（Wheel of Life）— 多面向平衡偵測
- **SIGN 天賦識別**（停止無效努力）— 心流與能量偵測
- **好時光日誌**（Designing Your Life）— 活動能量追蹤
- **錯位偵測**（Feel-Good Productivity）— 價值與行動一致性
- **能量投資組合**（Feel-Good Productivity）— 注意力分布

但用戶永遠不需要知道框架名稱。他們只需要看到結果。

### 第四層：討論模式

討論不只是另一種輸入。它是 Zentropy 最強的閉環加速器。

#### 怎麼運作

用戶有一個模糊的念頭、一個還沒想清楚的決定、一個反覆出現的問題。

進入討論模式後：

1. **AI 從你的地圖拉出脈絡** — 「你最近三週跟這件事有關的想法有 8 個，跟工作不滿有關的有 5 個」
2. **AI 用思考框架幫你結構化** — 但用戶不需要知道框架名稱。AI 根據討論內容自動選擇
3. **討論過程自動回饋到地圖** — 新的想法、做出的決定、發現的模式，全部進入 Map Layer

#### 框架隱形，AI 選擇

| 討論內容 | AI 自動套用 | 用戶看到的問題 |
|---------|------------|--------------|
| 「要不要做 X」 | 決策矩陣 / Pre-mortem | 「最壞的情況是什麼？你能接受嗎？」 |
| 「為什麼我一直拖延 X」 | 5 Whys / 冰山模型 | 「你覺得真正擋住你的是什麼？」 |
| 「不知道接下來要幹嘛」 | 奧德賽計畫 / 天命四元素 | 「如果有三條路，你會怎麼畫？」 |
| 「最近覺得哪裡不對」 | 錯位偵測 / 生命之輪 | 「你覺得是哪個面向出了問題？」 |
| 「這件事值不值得做」 | 機會成本 / NICE Goals | 「如果不做這件事，你會拿時間做什麼？」 |

#### 討論的雙向回饋

討論過程中產生的知識自動進入地圖：

- 新的想法 → 地圖上長出新節點
- 做出的決定 → 可以直接變成任務
- 發現的模式 → 加速 insight 成熟
- 釐清的價值觀 → 強化錯位偵測的基準

舉例：你在討論中說了「其實我真正想做的不是創業，是想做一個自己的作品」。這句話進入 Map Layer，之後錯位偵測會用這個作為基準。

#### 為什麼討論是最高品質的輸入

- 普通輸入：一次一個節點
- 完成反思：節點有了能量色彩
- 討論：一次長出一整片區域 + 連結 + 核心錨點

對地圖來說，討論是一個加速成長事件——做完一次討論，打開地圖會發現長出了很多東西。

### 第五層：讓 AI 回饋更貼近你

當 Map Layer 足夠成熟後，AI 的角色升級：

- 不只是整理，而是基於你一路累積的脈絡，給更貼近的提醒
- 不是 generic advice，而是「你上次這樣做的時候覺得很消耗，確定要再做一次嗎？」
- 不是外部知識，而是你自己的模式被重新映照回來
- 討論模式中的 AI 越來越了解你，問出的問題越來越精準

## 7. 產品不是什麼

### 不是另一個 Todo List

Zentropy 可以從任務開始，但它同時接住想法、靈感、心得、反思。如果只剩下待辦清單，Zentropy 就退化成 todo app。

核心切割：**公司的任務有別的工具管。Zentropy 管的是你自己的事——你在想什麼、在意什麼、忽略什麼。**

### 不是傳統第二大腦工具

Obsidian、Heptabase、Tana 要求先建系統再開始用。Zentropy 從丟東西進來開始，系統在後面長出來。

### 不是自我成長教練 App

Zentropy 不要求你每天寫日記、打分、做反省。它不教你、不矯正你。它只是照給你看。改不改是你的事。

完成反思也不是日記——它是一句話，在最自然的時刻（剛做完一件事），做最小的回顧。

### 不是 Consumer 版 ZenOS

對使用者來說，不應出現 ontology、governance、MCP、federation 等語言。使用者只需要感受到：

- 丟進來就比較不亂
- 用久了開始看見自己的方向
- 偶爾被提醒一下自己沒注意到的事

## 8. 核心使用者

Zentropy 不該先打最會自己搭工具的進階使用者。它更適合這類人：

> **每天很忙、腦子裡很多事在跑，知道應該想清楚方向但沒時間停下來的人。**

### 核心 TA

#### A. 忙到失焦的知識工作者

- PM、marketer、顧問、創作者、小型團隊成員
- 腦中很多事情同時在跑，願意記錄但不願意為了記錄再做很多管理
- 核心需求：先不亂，然後有人幫我看我在往哪走

#### B. 有記錄習慣但很難長期維持的人

- 試過 Notes app、Todo app、Obsidian、日記
- 失敗原因：太麻煩、太散、太重、太難持續
- 核心需求：能先開始，然後真的看到回報

### 次要 TA

#### 對自我理解有興趣，但不喜歡高負擔反思的人

- 不要做太多表單、不要每天寫長日記
- 更容易接受：先正常用，之後偶爾被提醒一下

### 暫時不是 TA

- 自己會搭完整工具鏈的 power users
- 只想要嚴格任務管理的人
- 主要目的是 PKM 系統建構的人
- 期待立刻得到深度人生教練式分析的人

## 9. 核心產品體驗

### 9.1 丟進來

Zentropy 的第一個體驗不是分類，而是接住。

使用者可以記下：

- 一件待辦
- 一個突然想到的點子
- 一段書摘
- 一段感受
- 一個看到的連結

三個入口：

- `任務`（要做的事）
- `想法/心得`（要記的）
- `討論`（要想清楚的）

系統不要求先決定這是什麼，才能開始輸入。

### 9.2 立刻理出頭緒

輸入之後，Zentropy 至少要讓使用者感受到：

- 事情被接住了
- 沒有那麼亂了
- 它和既有的東西有關聯
- 可以回來找到

#### 任務流

- 正規化內容
- 判斷是追加到既有任務，還是建立新任務
- 產生 next step / checklist

> 任務流的成功標準：讓事情立刻可執行。

#### 想法流

- 保留 raw input
- 產生輕量摘要
- 產生輕標籤（Area / Type / Thread）
- 連到相關內容

> 想法流的成功標準：讓使用者知道這個想法有被接住、被保留、之後找得回來。

#### 討論流

- 用戶提出一個問題或模糊念頭
- AI 從個人地圖拉出相關脈絡
- AI 用適合的思考框架引導結構化對話
- 討論中產生的想法、決定、發現自動回寫地圖

> 討論流的成功標準：讓使用者把模糊的念頭想清楚，同時地圖因此加速成長。

### 9.3 地圖生長

每次輸入後，用戶的個人地圖都在視覺化地變化。

#### 即時回饋（每次輸入）

輸入落在地圖上對應的位置。用戶看到那個區域變大了一點。系統不說話，地圖自己說。

#### 成長視覺

- 輸入越多的區域越大、越茂盛
- 有反思的節點有能量色彩（亮 = 高能量，暗 = 消耗）
- 完全沒有輸入的區域保持空白
- 一兩週後，節點之間開始長出連結

#### 體驗節奏

| 時間 | 用戶看到的 | 用戶的感覺 |
|------|-----------|-----------|
| Day 1 | 東西落在地圖某個位置 | 有被接住 |
| Day 2-3 | 同一個區域越來越大 | 原來我最近一直在想這件事 |
| Day 5-7 | 反思讓某些節點亮起來 | 做完這件事特別有感覺 |
| Week 2 | 地圖有了明顯形狀，某些區域空白 | 不需要 insight 就知道自己怎麼了 |
| Week 2-3 | 節點之間長出連結 | 原來這幾件事是連在一起的 |
| Week 3+ | 第一個正式 insight 浮現 | 它只是確認了我已經隱約感覺到的 |

### 9.4 完成反思

反思有兩個時機，都從「你完成了什麼」出發，不從「你還沒做什麼」出發。

#### 即時反思（完成當下）

完成任務時，系統顯示一個輕量入口：

> 「做完了。有什麼想法嗎？」

用戶可以自然書寫，系統自動識別：

| 用戶可能寫的 | 系統識別為 | Map Layer 用途 |
|-------------|-----------|---------------|
| 「比想像中順利」 | 能量正向 | 標記此任務/主題為高能量 |
| 「不想做但不得不做」 | 能量消耗 | 標記為消耗源 |
| 「做完很有成就感」 | 滿足感高 | SIGN 指標：完成後滿足 |
| 「其實可以不用做」 | 優先序反思 | 錯位偵測素材 |
| 「下次要用不同方法」 | 學習 | 行為模式素材 |
| （跳過） | 無反思 | 僅記錄完成事實 |

#### 晚間回顧（可選）

晚上推一張今天的「完成清單」——不是待辦，是你今天做到的事：

> 「你今天完成了這些。有沒有哪件讓你特別有感覺？」

用戶可以：
- 對某件事點一下標記（如「有成就感」「很消耗」「沒感覺」）
- 對某件事寫一句話
- 什麼都不做，直接關掉

關鍵差異：**永遠先展示成就，不展示缺口。** 沒有「你還有 N 件沒做」。

#### 設計約束

- 跳過是正常行為，UI 不能暗示「你應該寫」
- 輸入框暗示一句話就好，不是要你寫作文
- 晚間回顧只展示已完成項目，不展示未完成項目
- 不對反思做評價、打分、或「你應該...」

### 9.4 Insight 浮現

當輸入和反思累積到足夠程度，insight 在 Map Layer 自然浮現。

浮現方式：

- **Push notification**（手機）：最重要的 insight 才推
- **App 內卡片**：打開 App 時在首頁顯示
- **Digest**（可選）：用戶可以選擇每週收一次摘要，但這不是預設行為

Insight 的 UI 語氣：

- 不是「你應該...」→ 是「你有沒有注意到...」
- 不是「建議你...」→ 是「你最近的情況是...」
- 不是報告 → 是一面鏡子

### 9.5 從 Insight 到行動（可選）

看到 insight 之後，用戶可以：

- **不做任何事**（完全合法，不施壓）
- **把 insight 變成一個任務**（「我要開始每週留時間給創作」）
- **開一個討論**（「我想聊聊為什麼我一直忽略這件事」）
- **調整自己的優先序**（insight 影響了他對什麼重要的判斷）

這些行動又會回到 Flow Layer，形成新的輸入，閉環完成。

## 10. Aha Ladder

### Aha 1：原來什麼都可以先丟進來

最早的 activation moment。腦子裡的東西少了一些。

### Aha 2：丟進來之後地圖變了一點

第一次看到自己的輸入讓地圖長出東西。開始好奇「這個會變成什麼」。

### Aha 3：我的地圖居然長成這個形狀

用了一週，發現某個區域特別大、某些區域空白。不需要 insight 就知道自己最近怎麼了。

### Aha 4：做完一件事寫一句話，地圖上那個點亮了

發現反思不是寫日記，是一句話的事。而且有視覺回饋——高能量的事情在地圖上發亮。

### Aha 5：討論完一次，地圖長出一整片

第一次用討論模式，發現模糊的念頭被想清楚了，而且地圖上多了好多新東西。

### Aha 6：它居然知道我最近一直在想什麼

第一次收到正式 insight。但其實已經從地圖上隱約感覺到了。Insight 是確認，不是驚喜。

### Aha 7：它照出來的，和我以為的不一樣

錯位偵測生效。「你說健康很重要，但最近一個月零輸入。」這是產品和競品真正拉開距離的時刻。

### Aha 8：它比我自己更知道我最近在意什麼

長期價值。用戶開始信任 Zentropy 對自己的理解。討論模式中 AI 問的問題越來越精準。

## 11. 和競品真正不同的地方

### 與 Todo / PM 工具的差異

Todoist、TickTick、Things 管的是**事情**。Zentropy 管的是**你**——你在想什麼、在意什麼、忽略什麼。

公司的任務用別的工具管。Zentropy 管的是你自己腦子裡的東西。

### 與筆記 / 第二大腦工具的差異

Obsidian、Heptabase 要求你先建系統。Zentropy 從丟東西進來開始。

最大的差異：筆記工具只存，不照。Zentropy 會把你存的東西照回給你看。

### 與自我成長 App 的差異

大部分 journaling / self-help app 要求你每天寫日記、填表、打分。

Zentropy 不要求你做額外的事。你本來就會想事情、做事情。Zentropy 從你已經在做的事裡面，照出模式。

完成反思也不是日記——它在最自然的時刻（剛完成一件事），用最小的方式（一句話），做本來做不到的事（好時光日誌）。

### 與通用 AI 工具的差異

ChatGPT、Claude 很強，但它們解的是單次互動。

Zentropy 的討論模式也用 AI 對話，但差異在於：它記得你三週前想過什麼、上個月在意什麼、你做完哪件事特別有能量。每次討論都站在你一路累積的個人地圖上，不是從零開始。

### 真正的競品

Zentropy 真正要取代的不是 Todoist 或 Day One。是：

- Notes 裡堆了 200 條再也沒打開的備忘
- Line 對話框裡傳給自己的一句話
- 凌晨三點腦子裡轉的那些念頭
- 洗澡時想到的好點子，擦乾就忘了

這些東西現在佔著你的腦容量，但沒有任何地方可以放。Zentropy 是那個地方。

## 12. 商業潛力

Zentropy 的位置是：

> **從管住混亂切入，逐步長成一個個人方向系統。**

- 下載理由很具體：腦子太亂，需要一個地方倒出來
- 留存理由會變強：insight 越來越準、越來越像一面鏡子
- 完成反思提高資料品質，加速 insight 精準度
- 視覺化空間大：可用地圖、面向、狀態、趨勢來呈現
- 可往 premium 發展：更深的 insight、更長的趨勢、更多框架映射

## 13. 產品演進原則

### 原則 1：先賣管住混亂，不先賣看見方向

使用者下載產品，先是為了讓腦子裡的東西有地方放。
看見方向是後面的價值，不是第一層承諾。

### 原則 2：反思不強迫，有做就加分

完成反思是閉環的關鍵橋梁，但絕不能變成負擔。
30% 的完成反思率就足以產生有意義的 insight。

### 原則 3：Insight 有發現才說，不排程推送

Zentropy 不是週報工具。在最自然的時刻告訴你最有意義的事。
寧可一個月只推一次但每次都讓你停下來想，也不要每週推一次讓你麻木。

### 原則 4：照鏡子，不說教

Zentropy 不應該給人「我要幫你成為更好的人」的感覺。
它照出事實，讓你自己決定。「這是你要的樣子嗎？」

### 原則 5：框架在底層，用戶看結果

生命之輪、SIGN、錯位偵測等框架是 Map Layer 的底層邏輯。
但用戶永遠只看到結果，不看到框架名稱。
討論模式中 AI 用思考框架引導對話，但用戶只看到好問題，不看到框架名。

### 原則 6：地圖是產品的心臟

地圖不是附加功能，是核心體驗。用戶打開 Zentropy 應該先看到自己的地圖在生長，而不是一個空白的輸入框。

### 原則 7：前台秩序層與後台知識層必須分離

Zentropy 前台不應把每一筆 consumer 輸入直接當成 ZenOS Core mutation。
前台先用 Flow / Map 兩層接住與整理，只有成熟知識才 promotion 到 ZenOS。

## 14. 明確不包含

- 不把 Zentropy 做成重型 PKM 工具
- 不把 Zentropy 做成純任務管理工具
- 不把 Zentropy 對外包裝成心理分析 App
- 不要求使用者一開始就理解知識圖譜概念
- 不把差異化建立在更多欄位、更多設定、更多分類

- 不強迫用戶在完成任務時必須反思

## 15. 下一步優先序

### P0

- 三個輸入入口：任務、想法/心得、討論
- 讓輸入後的東西立刻比較有頭緒
- 個人地圖的基礎視覺化（區域成長、大小變化）
- 完成任務時提供輕量反思入口（可跳過）

### P1

- 地圖生長的完整體驗：能量色彩、連結生長、空白區域
- 討論模式 MVP：AI 拉脈絡 + 基礎思考框架引導
- 反思資料進入 Map Layer，開始累積能量 / 滿足感訊號

### P2

- 第一批 insight 上線：沉默警報、隱藏模式、重心快照
- 討論模式進階：更多框架、討論摘要回寫地圖
- 晚間成就回顧

### P3

- 錯位偵測上線（設定的價值 vs 實際行為）
- 能量峰值與消耗警報
- insight 從 App 內卡片擴展到 push notification

### P4

- AI 回饋基於長期 Map 提供更貼近的提醒
- 趨勢分析：你的重心在過去三個月怎麼移動
- 可選的框架映射（5 Types of Wealth、奧德賽計畫推演）

## 16. Hero Messaging

### 對外敘事結構

**問題（用戶秒懂的）：**

> 你忙了一整週，但你說得出來這週最重要的事是什麼嗎？

**第一層承諾（管住混亂）：**

> 把腦子裡的東西丟進來。不用分類、不用整理。丟進來就比較不亂。

**第二層承諾（看見方向）：**

> 用久了之後，Zentropy 會開始告訴你：你的時間花在哪、什麼正在被推進、什麼一直在被你忽略。

**切割（不是什麼）：**

> 這不是任務管理工具。你公司的任務已經夠多了。
> 這不是自我成長 App。你不需要每天寫日記。
> 這是一個幫你看清楚「你的忙到底在往哪裡走」的工具。

### Anti-positioning（不能說的話）

| 避免 | 原因 |
|------|------|
| 「AI 任務管理」 | 瞬間被歸類為 Todoist 競品 |
| 「認識自己」「自我成長」 | 聽起來像功課 |
| 「知識圖譜」「ontology」 | 用戶不在乎底層 |
| 「第二大腦」 | 被 Obsidian 佔走了 |
| 「讓一切井然有序」 | 太理性，沒有情緒勾子 |
| 「AI 幫你分析」 | 聽起來像被監控 |
