# Feature Spec: Zentropy Discussion Mode

> 本文件定義 Zentropy 第三個輸入入口「討論」的產品規格。討論模式讓用戶和 AI 一起把模糊的念頭想透，討論過程自動回饋到個人地圖。
>
> 依賴文件：
> - [SPEC-zentropy-v5_1-product-definition.md](SPEC-zentropy-v5_1-product-definition.md) — 產品主張與三入口定義
> - [SPEC-zentropy-dual-graph-architecture.md](SPEC-zentropy-dual-graph-architecture.md) — Discussion Input Flow 的資料流定義

## 1. 定位

### 討論不是聊天

ChatGPT / Claude 的對話是從零開始。Zentropy 的討論是站在你的個人地圖上。

差異：

| 通用 AI 對話 | Zentropy 討論 |
|-------------|-------------|
| 每次從零開始 | 自動拉出你最近在想什麼 |
| 你要自己提供 context | 地圖就是你的 context |
| 對話結束，知識消失 | 討論產出自動回寫地圖 |
| 給你建議 | 幫你想清楚 |

### 討論不是想法/心得

想法/心得是「記下一句話」。討論是「把一件事想透」。

- 想法是單向的（你 → 系統）
- 討論是雙向的（你 ↔ AI）
- 想法產生一個節點，討論產生一整片區域

### 為什麼需要討論

用戶有三種狀態：

1. **知道要做什麼** → 任務入口
2. **有個念頭想記下** → 想法入口
3. **有件事想不清楚** → 討論入口

第三種狀態是最常見但最沒有工具解決的。你不是要記錄，你是要思考。但一個人想容易打轉，需要有人問你問題。

## 2. 使用者體驗

### 2.1 進入討論

用戶在三個入口選擇「討論」，然後用自然語言描述他想討論的事：

- 「我一直在想要不要辭職去創業」
- 「最近覺得哪裡不對，但說不出來」
- 「不知道接下來應該把時間花在哪」
- 「這個 side project 到底值不值得繼續做」

### 2.2 AI 回應結構

AI 的第一則回應包含兩部分：

**Part A — 脈絡回顧（來自地圖）：**

> 「從你最近的記錄來看，跟這件事有關的想法有 8 個，最近一個是三天前。你上個月完成的任務裡，有 3 個跟這個方向有關，其中 2 個你標記為『很有成就感』。」

這段讓用戶知道：AI 不是從零開始，它知道你之前在想什麼。

**Part B — 引導問題（來自框架）：**

> 「我們可以從幾個角度來想：
> → 如果真的做了，你最想做的是什麼？
> → 為什麼是現在想做？
> → 最壞的情況是什麼？你能接受嗎？
> 從哪個開始？」

用戶選擇一個方向，或者自己帶話題。AI 跟著走。

### 2.3 討論過程

討論是自然對話，但 AI 在背後做幾件事：

1. **持續引導結構化**：用思考框架推進對話，但不暴露框架名
2. **適時帶入地圖脈絡**：「你之前說過...」「你上次做完某件事的時候覺得...」
3. **識別有價值的片段**：標記新想法、決定、價值觀釐清、模式發現
4. **不急著給結論**：AI 的角色是問好問題，不是給答案

### 2.4 討論結束

用戶可以隨時結束討論（或自然收尾）。結束時系統：

1. 產生一段**討論摘要**（2-3 句，抓住核心）
2. 列出討論中產生的**可行動項目**（如果有）
3. 用戶可以選擇把某些項目轉為任務

討論摘要和識別出的知識自動進入 Map Layer。

### 2.5 討論後的地圖變化

做完一次討論，用戶打開地圖會看到：

- 相關區域明顯長大了
- 可能出現新的連結（討論中發現的關聯）
- 如果釐清了某個價值觀，該區域會有「核心錨點」的視覺標記

這是討論模式最重要的 payoff：**你看到自己的思考在地圖上長出了形狀。**

## 3. 思考框架庫

### 3.1 框架選擇邏輯

AI 根據討論內容的語意自動選擇框架。用戶永遠不看到框架名稱。

| 用戶的問題模式 | AI 選擇的框架 | AI 實際問的問題 |
|-------------|-------------|--------------|
| 「要不要做 X」 | 決策矩陣 / Pre-mortem | 「最壞的情況是什麼？你能接受嗎？」 |
| 「為什麼我一直拖延 X」 | 5 Whys / 冰山模型 | 「你覺得真正擋住你的是什麼？」 |
| 「不知道接下來要幹嘛」 | 奧德賽計畫 / 天命四元素 | 「如果有三條路，你會怎麼畫？」 |
| 「最近覺得哪裡不對」 | 錯位偵測 / 生命之輪 | 「你覺得是哪個面向出了問題？」 |
| 「這件事值不值得做」 | 機會成本 / NICE Goals | 「如果不做這件事，你會拿時間做什麼？」 |
| 「我想做 X 但不知道怎麼開始」 | 原型測試 / 5W1H | 「最小的第一步是什麼？」 |
| 「兩個選項之間選不了」 | 10/10/10 / 雙欄比較 | 「10 個月後你會怎麼看這個決定？」 |

### 3.2 框架的使用原則

- **一次只用一個主框架**：不要同時套三個，會讓對話變成問卷
- **框架是引導，不是流程**：如果用戶帶了另一個方向，AI 跟著走
- **自然融入**：框架的問題應該像朋友在問你，不像教練在考你
- **可以不用框架**：有些對話不需要結構化，AI 應該判斷何時純粹傾聽

### 3.3 框架來源

初期框架庫來自已驗證的思考模型：

- **5W1H** — 基礎結構化
- **5 Whys** — 深層原因挖掘
- **Pre-mortem** — 決策風險預判
- **10/10/10 法則** — 時間視角轉換
- **機會成本思維** — 資源取捨
- **奧德賽計畫**（DYL）— 多路徑想像
- **NICE Goals**（高效原力）— 目標設定
- **冰山模型**（停止無效努力）— 表層到深層
- **天命四元素**（發現天賦）— 天賦 × 熱情 × 態度 × 機會

框架庫可隨時間擴充，但擴充標準是：**這個框架能幫用戶把某類問題想清楚**，不是「這個框架很有名」。

## 4. 地圖回饋機制

### 4.1 討論過程中的即時識別

AI 在對話過程中即時識別有價值的知識片段：

| 用戶說的 | 系統識別為 | 寫入 |
|---------|-----------|------|
| 「其實我真正想做的是 X」 | 價值觀釐清 | Map Layer 核心錨點 |
| 「我決定先做 A 不做 B」 | 決定 | task candidate（需確認） |
| 「原來我一直在逃避這件事」 | 模式發現 | Map Layer pattern |
| 「這個問題跟上次那件事有關」 | 新連結 | Map Layer relationship |
| 「我之前沒想過可以這樣」 | 新想法 | idea store |

### 4.2 討論結束時的批量寫入

討論結束後，系統一次性做：

1. 討論摘要 → Map Layer thread
2. 識別出的 ideas → idea store（自動掛到相關 area / theme）
3. 價值觀錨點 → Map Layer stable anchor（高信心，可作為錯位偵測基準）
4. 決定 → task candidate list（展示給用戶，用戶選擇哪些轉為任務）

### 4.3 討論觸發 Map Layer 聚合

每次討論結束後，應觸發一輪 Map Layer 的背景聚合 job，因為：

- 討論產生的節點量大（相比單條輸入）
- 討論產生的連結可能跨多個 area
- 新的核心錨點可能改變既有 clustering 結果

這個聚合不需要用戶等待，但用戶下次打開地圖時應看到成長。

## 5. 設計約束

### 5.1 討論的長度

- 不限制最大長度，但 AI 應在適當時候引導收尾
- 典型的有效討論約 5-15 輪對話
- 超過 20 輪時，AI 可建議「要不要先到這裡，改天繼續？」

### 5.2 討論的儲存

- 完整對話歷史保留在 Flow Layer（raw conversation store）
- 用戶可以回看過去的討論
- 但地圖上只保留萃取後的知識，不保留逐字稿

### 5.3 討論和其他入口的關係

- 從 insight 可以直接開一個討論（「我想聊聊為什麼我一直忽略健康」）
- 從想法可以升級為討論（「這個想法我想再深入想想」）
- 討論中產生的任務和想法，和直接輸入的任務和想法，在 Flow/Map Layer 中無差異

### 5.4 AI 的角色邊界

- **AI 問問題，不給答案**：「你覺得呢？」比「你應該...」重要
- **AI 帶入脈絡，不做判斷**：「你之前說過 X」不等於「所以你應該 Y」
- **AI 用框架引導，不走流程**：如果用戶走了另一個方向，AI 跟著走
- **AI 可以說「我不確定」**：不是所有問題都適合結構化思考

## 6. 與既有模組的關係

### 6.1 與 Brain Dump 的關係

Brain Dump 處理任務和想法的快速輸入。討論是第三條路徑，在 Brain Dump 的 routing 層加入 discussion intent 判斷。

若用戶在任務或想法入口輸入了明顯的「想討論」內容（如「我在想要不要...」），系統可輕提示：「這看起來可以開一個討論，要嗎？」

### 6.2 與 Librarian Engine 的關係

Librarian 現有的 rolling summary、correction delta、pattern detection 能力，可以作為討論模式的脈絡來源。討論產出的高品質知識也會加速 Librarian 的聚合效率。

### 6.3 與 Coach Agent 的關係

Coach Agent 的晨報/晚報推播可以包含「你可能想討論一下這件事」的引導，把被動的 insight 轉化為主動的思考。

## 7. Done Criteria

1. 用戶可以從三入口選擇「討論」開始對話
2. AI 能從個人地圖拉出相關脈絡作為對話開場
3. AI 能根據問題類型選擇適當的思考框架引導對話
4. 討論中識別的想法、決定、價值觀能自動寫入 Map Layer
5. 討論結束後用戶打開地圖能看到成長
6. 用戶可以從討論中產生的決定直接建立任務
